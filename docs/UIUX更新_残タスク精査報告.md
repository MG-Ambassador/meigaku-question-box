## 3. 再現済み不具合：先に修正する5項目

### R01：共有経由で未保存編集が失われ、URLと対象が不一致になる

- 優先：最優先。根拠：ブラウザーで再現済み。原則：安心・信頼、Straight。
- 再現：ルームAの設定名を編集 → ルーム一覧を開く → ルームBの共有を開く → 共有を閉じてAへ戻る。
- 結果：未保存確認なしで対象がBへ切り替わり、Aの編集が消える。URLのeventはAのまま残る。
- 対象：`app/admin/panel.tsx`のルーム一覧内共有操作。navigateを経由せずsetEventIdを呼んでいる。
- 対応：共有対象を編集中のルームと別に保持し、共有だけでは画面を切り替えない。ルーム切替が必要な操作は共通の未保存確認とURL更新を通す。
- 完了条件：他ルームを共有しても編集中のルーム・入力・URLが変わらない。共有リンクは選んだ対象を指す。回帰テストを追加する。

### R02：「保存して移動」が受付停止確認を迂回する

- 優先：高。根拠：ブラウザーで再現済み。原則：Straight、安心・信頼。
- 再現：受付中のルームでスイッチをOFF → 質問タブへ移動 → 保存して移動。
- 結果：通常の保存操作にある受付終了確認を表示せず、open=falseが保存される。
- 対象：PanelのhandleSaveAndNavigateとEventSettingsのsaveRef／form送信。
- 対応：入力検証、受付停止確認、保存を共通の保存入口へ集約し、保存成功後にだけ移動する。取消・保存失敗・競合では編集と現在画面を維持する。
- 完了条件：通常保存と移動前保存で同じ確認を行う。確認取消で停止も移動もしない。遅延中の重複保存と途中移動もテストする。

### R03：集計から質問へ進むと履歴を二重追加する

- 優先：高。根拠：ブラウザーで再現済み。原則：Straight、Minimal。
- 再現：集計 → 大学生活の質問を見る → ブラウザーの戻るを1回。
- 結果：同じ質問画面・URLに留まり、集計へ戻らない。
- 対象：EventWorkspaceのfilterFromInsight／returnToInsightsとPanel.executeNav。
- 対応：画面遷移と条件更新を1つの操作として処理し、履歴の書き込みを一箇所へ集約する。
- 完了条件：1回の移動に1つの履歴を追加。戻る1回で元画面、進む1回で移動先に戻り、URL・条件・見出しが一致する。

### R04：新規作成の入力を確認なしで破棄する

- 優先：高。根拠：ブラウザーで再現済み。原則：安心・信頼、Minimal。
- 再現：新しいルームの名前を入力 → Escapeで閉じる → 新しいルームを再度開く。
- 結果：破棄確認がなく、再表示時は空。既存設定の未保存保護は新規作成に接続されていない。
- 対象：Panelの新規作成AppSheet、createRevision、EventSettings。
- 対応：新規作成の変更状態も管理し、閉じる・Escape・背景クリックでは破棄確認を行う。取消はシートと入力を維持する。保存中は閉じる操作を防ぐ。
- 完了条件：3種類の閉じ方で入力を無確認破棄しない。保存・取消・明示的破棄を検証する。

### R05：受付スイッチのON表示が枠からはみ出す

- 優先：高。根拠：今回のブラウザー測定で再現済み。原則：Contrast、Straight。
- 測定：390px幅、ONのトラックはx=303〜351、幅48px・高さ28px。thumbはx=346〜368で右端が17pxはみ出す。OFFでは枠内に収まる。
- 原因：部品のCSS translate（calc(100% - 2px)）と画面CSSのtransform:translateX(20px)が重複して適用される。
- 対象：`components/ui/switch.tsx`と`app/globals.css`のaccepting-switch。
- 対応：移動量の指定を一箇所へ集約し、左右の内側余白を揃える。見た目のトラックと48px以上の操作領域を分ける。
- 完了条件：ON/OFF、狭幅、拡大、無効、動きを減らす設定でthumbが枠内に収まり、左右余白が等しい。寸法の回帰検証を追加する。

### 検査範囲と制限

UIテストはローカル静的出力とAPI／認証モックを使う。ブラウザーはこのMacのChrome。幅変更と文字200%は実機の代替と扱わない。個人別お気に入りの実認証、Firestore条件検索・件数・インデックス、OS共有先の動作はR14で確認する。

LintはNext.jsアプリ・共通部品・テスト・スクリプトを対象とし、出力物、別パッケージのserver、旧フレームワークlegacyを除外する。レジストリ部品の例外はcomponents/uiとhooks/use-mobileに限定。アプリ全体の検査ルールは有効。APIは独立パッケージの型検査とテストで扱い、今回のフロントエンド検査合格をAPI全体の合格とはしない。
