# 運営ID・パスワード

来場者はログインなしで質問を投稿。運営用ページは `/admin`。
メールアドレス・ChatGPTアカウント・Supabaseは不要。

## 最初の運営責任者

IDは `mga-owner`。初回のランダムな仮パスワードは、公開されないローカルのログイン情報ファイルで所有者へ渡す。
初回ログイン後に15〜128文字の本人用パスワードへ変更するまで、質問閲覧・イベント編集・担当者管理はすべて拒否する。
`INITIAL_OPERATOR_HASH` はサイトのサーバー側シークレットに保存したscryptハッシュ。初回の固定ID作成にのみ使用し、既存アカウントのパスワードを上書きしない。初回作成後は削除して再公開してもよい。平文パスワードを環境変数・ソース・移行SQLへ保存しない。

## 担当者管理

責任者が「担当者の管理」から表示名とIDを登録。仮パスワードはその画面で一度だけ表示されるため、本人へ個別に渡す。担当者は初回変更後、イベント作成・質問閲覧・分析を利用できる。
再発行・利用停止は対象者の全セッションを無効にする。通常担当者は他人のアカウントを管理できない。責任者自身の利用停止は不可。
パスワード変更は現在のパスワードが必要。変更により他端末のログインは無効。
担当者が忘れた場合は責任者が再発行。責任者自身が忘れた場合は、サイト所有者が認証済みの保守経路で本人を確認して復旧する（公開ページに無認証の再発行機能は設けない）。INITIAL_OPERATOR_HASHを変更するだけでは既存責任者をリセットできない。

## 実装上の保護

- scrypt N=16384,r=8,p=5、個別のランダムsalt。平文パスワードは保存しない。
- 256bitのランダムセッション、DBにはSHA-256ハッシュのみ。HttpOnly/Secure/SameSite=Strict、1時間で期限切れ。
- 各APIで有効な担当者・資格情報バージョンを確認。初回変更前、利用停止、再発行後、期限切れ、偽造Cookieは拒否。
- ID単位で15分10回、IP単位で10分30回の試行制限。未登録IDでも同じ失敗メッセージとハッシュ計算。
- 書き込みは同一Origin＋JSON、入力サイズ8KB上限。SQLはパラメーター化。
- 旧メール認証APIは410、旧メールセッション・ChatGPTヘッダーは運営権限として使用しない。
- 既存のメール用テーブルは移行履歴として保持するが、認証に使用しない。

基準: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[Cloudflare node:crypto](https://developers.cloudflare.com/workers/runtime-apis/nodejs/crypto/)。
